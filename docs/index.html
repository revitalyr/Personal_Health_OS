Personal Health OS

Architecture Documentation — Microservice-based Personal Health Record system built in Rust with Axum, PostgreSQL, NATS, and Redis.

System Overview

Personal Health OS is composed of 9 microservices and 9 shared crates, organized as a Cargo workspace. The API Gateway serves as the single entry point, routing requests to downstream services. PostgreSQL provides the primary data store, NATS enables async event-driven communication, and Redis handles caching.

Timeline Service Axum :8081

Central event store and timeline computation. Manages the append-only medical_events table and publishes events to NATS.

Document Processor Axum :8082

Document upload, OCR processing, DICOM processing, NLP entity extraction, and manual data entry. Orchestrates the processing pipeline asynchronously.

Patient Management Axum :8085

Full hospital patient management: CRUD, encounters, vitals, allergies, medications, discharge, and audit trail.

Doctor Access Service Axum :8084

QR-code-based temporary doctor access to patient data. Issues 15-minute JWT tokens.

AI Report Service Axum :8083

AI-powered medical report generation (currently a stub/placeholder).

Appointment Scheduling Axum

Full appointment lifecycle: availability, booking, rescheduling, cancellation, reminders (24h + 2h), and statistics.

Billing & Invoicing Axum

Invoice generation, payments, insurance claims, service charges, AR aging reports.

Licence Management Axum

SaaS licence key generation (RSA-signed), validation, hardware fingerprinting, usage analytics, tiered feature management.

Audit & Security

  • Structured audit trails: patient_events, appointment_events, licence_events
  • PGP encryption via pgcrypto for PII columns with secure views for transparent decryption
  • 8 valid event_type values: Symptom, Medication, LabResult, DoctorVisit, Diagnosis, Document, Vitals, Encounter
